## 방법과 한계
- 실제 앱 코드를 그대로 쓰고 LLM만 적대적/오작동 생성기로 바꿔 끼웠다. Ollama·BGE-M3 없이 실행된다.
- 실제 모델의 행동(주입 순응 여부 등)과 BGE-M3 점수 분포는 시험하지 못했다 → 판정 불가.
- 검색 결과 자체는 해시 임베더와 3개짜리 합성 문서라 검색 품질 결론은 내지 않는다.

## 영향 범위(코드 흐름)
- `validate_grounding` 은 CoreRAG, LangGraph 워크플로, 웹 검색 보조가 함께 쓴다. 한 곳을 고쳐 세 경로가 같이 바뀐다.
- CoreRAG 와 워크플로의 거절 문구는 일치하도록 시험으로 고정했다.
- 프롬프트에 문장이 하나 추가되어 **생성 결과가 조금 달라질 수 있다** → 최종 평가는 이 수정 적용 후 다시 돌려 발표 수치로 쓸 것.
- "답 없는 질문 거절" 집계: 모델의 정직한 거절은 이제 `model_refused` 로 보이므로, 거절 원인 구성이 이전 보고서(전부 grounding_failed)와 달라진다.
