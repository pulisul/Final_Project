# 폴더에서 문서 찾아 질문하기 (Streamlit)

```bash
PYTHONPATH=src INTELLECTAGENT_CONFIG=config/core.production.json streamlit run app_streamlit.py
# 또는 run_real_env.sh app
```

## 사용 순서 (사이드바 "📂 폴더에서 문서 찾기")
1. **문서가 많은 폴더 추천**(선택): 홈 아래 Documents/Downloads/Desktop/Notes/Obsidian/OneDrive 중 지원 파일이 있는 곳의 개수만 센다. 색인하지 않는다.
2. 폴더 경로를 입력하고 **찾아보기**: 하위 폴더까지 훑어 *색인 대상 개수·용량·형식별 개수·내용이 같은 중복·제외된 파일과 사유·예시*를 보여 준다. 이 단계에서는 아무것도 저장·색인하지 않는다.
3. 맞으면 **이 폴더 등록 + 색인**: 폴더를 `index/ui_roots.json` 에 저장하고 색인한다. 다음 실행에서도 유지된다.
4. 본문의 질문 상자에 질문한다. 답 아래 출처에 파일 이름이 보인다.

## 안전 규칙 (기존 `corpus_scan` 재사용)
- 거부: 파일시스템 루트, 홈 폴더 전체, 시스템 폴더, `.git`/`.ssh`/`.aws`/`node_modules` 등, 색인·증거 저장 폴더 안.
- 제외: 숨김 파일/폴더, 심볼릭 링크, 비밀번호·키로 보이는 파일명(`*password*`, `*token*`, `*비밀번호*` 등), 빈 파일, 크기 제한 초과, 지원하지 않는 확장자.
- 등록된 폴더는 실행할 때마다 다시 검증한다(`ui_roots.json` 을 손으로 고쳐 위험 경로를 넣어도 건너뛴다).

## 알려진 한계 (추정이 아니라 코드로 확인한 것)
- **등록 해제 없음**: 색인에 들어간 조각을 지우는 기능이 없다(로드맵의 "삭제된 파일 정리"). 폴더에서 파일을 지워도 옛 조각은 남는다.
- 기본 설정(`config/core.json`)은 메모리 저장소 + 해시 임베더라 앱을 켤 때마다 자동으로 다시 색인하고, 검색 품질은 의미 검색이 아니다. 실제 사용은 운영 설정(`core.production.json`: Chroma + BGE-M3)으로 한다.
- 큰 폴더는 처음 색인이 오래 걸린다(진행률 표시 없음, 스피너만).
- 이 저장소를 만든 환경에서는 BGE-M3·Ollama·실제 .hwp 로 화면을 돌려 보지 못했다. 자동 테스트(`tests/test_app_folder_flow.py`)는 해시 임베더 + 가짜 생성기로 "찾기 → 등록 → 색인 → 재시작 → 질문 → 출처 표시" 흐름만 검증한다.
